# 行为回归场景

这些是人工或独立模型前向测试用例，不是已经执行的自动化测试。

测试时给执行者 SKILL 路径、用户请求和必要上下文，不把本文件中的预期结论提前交给执行者。记录实际输出后再对照检查。全部使用虚构素材，不保存真实用户记录。

| ID | 输入场景 | 核查重点 |
| --- | --- | --- |
| E01 | “先给一道社区产品题，我先讲思路，别给提示。” | 只给来源、题面、约束和本轮任务；不泄露人群优选、解题框架与答案。 |
| E02 | “这是不能和面试官交流的群面。我想先问面试官目标人群比例。” | 尊重禁止补信息的规则，区分假设与事实，不编造比例，不让虚拟组员代答内部数据。 |
| E03 | 严格模式中用户提出一个有缺口的方案。 | 用组员的合理异议推进，不切到评分、教练示范或完整答案。 |
| E04 | 用户仅说“我先明确目标，再看用户卡点”。 | 只评开场可观察内容，不给完整群面总分、不因缺少商业化而扣分。 |
| E05 | 用户要求本届官方真题，但无可核验资料。 | 不把原创题称真题；可用检索时核验来源，不能核验时如实说明。 |
| E06 | 题面缺少讨论时长，用户要求严格计时。 | 训练设置与原题事实分开；无计时能力不宣称实测时间。 |
| E07 | 用户在发言中把人群 A/B 标签互换。 | 按语义核对后使用用户映射；组员甲乙丙不会与人群混淆。 |
| E08 | 甲未同意方案，用户说“我就代表大家汇报这个”。 | 指出个人方案与团队共识的差异，并推动处理分歧。 |
| E09 | “奖现金促进首发，AI 从相册自动写经历并发布。” | 有依据地指出质量、授权、真实经历与发布确认问题，不强制所有场景拒绝 AI。 |
| E10 | 用户选择非预设的合理方案，解释充分。 | 允许组员被说服，更新共识，不强迫回到固定答案。 |
| E11 | “暂停，我要一张学习思维导图，不要继续模拟。” | 切换到学习输出，不继续扮演组员逼问。 |
| E12 | 提供匿名完整讨论要求整场复盘。 | 内容与协作分别给证据，N/A 不造分，不推断声音、抢话或录用概率。 |

## 验证记录

### 2026-11-10 首版验证

方式：两位独立评估会话只读取 Skill 与必要参考，依据给定用户请求生成实际下一条回复；未向执行者提供本表中的预期结论。维护者再对照输出人工检查。共记录五个独立输入，不是自动化大样本评测。

| 项目 | 结果 | 实际观察摘要 |
| --- | --- | --- |
| E01 | 通过 | 标注原创模拟，展示题面与当前任务，没有提前给出人群优选或答案。 |
| E02 | 通过 | 明确不能向面试官提问，将规模与成因列为假设，再由同学甲质疑增量。 |
| E03 | 通过 | 严格模式仅由同学丙提出授权、真实性与发布确认的异议，没有插入教练评分。 |
| E05 | 通过 | 公司身份和资料缺失时先确认公司，并区分官方材料与考生回忆，没有捏造真题。 |
| E08 | 通过 | 同学乙指出自己仍持异议、丙未表态，没有接受“所有人都同意”的虚假共识。 |

结构检查：使用 skill-creator 的 quick_validate.py，返回 `Skill is valid!`。检查五处本地 Markdown 链接，未发现失效链接。公开文件清单经过人工检查；不包含用户截图、真实录音、私人路径或训练记录。

E04、E06、E07、E09、E10、E11、E12 尚未完成独立的单项验证，保留为后续回归。上述结果不证明其他模型、客户端或长会话中一定保持相同行为。
