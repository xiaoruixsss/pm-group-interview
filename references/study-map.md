# 群面学习地图

用于用户明确要求学习笔记、思维导图或考前复习时。用户只要求出题时，不预先展示这份框架。

## 思维导图

```text
产品群面
├─ 审题
│  ├─ 目标与交付：用户结果、业务结果、汇报要求
│  ├─ 约束：人群、平台、资源、时间、不可触碰的边界
│  └─ 证据：事实／假设／待验证，不把补充设定当原题
├─ 用户与问题
│  ├─ 角色：使用、决策、付费与受影响的人
│  ├─ 场景：触发时刻、当前办法、具体卡点
│  └─ 聚焦：需求强度、替代成本、可解决程度
├─ 方案与取舍
│  ├─ 标准：价值、范围、成本、风险、证据
│  ├─ 比较：解决同一个目标的不同办法
│  ├─ 流程：入口→输入→处理→结果→行动→反馈
│  └─ 首期：做什么、不做什么、牺牲什么
├─ AI 与执行
│  ├─ 必要性：模板／规则／人工是否已经足够
│  ├─ 数据：来源、授权、引用、更新
│  ├─ 分工：建议、确认、执行、纠错
│  └─ 可靠性：成功率、失败恢复、时延与成本
├─ 商业与增长
│  ├─ 获客、激活、留存：各自要改变什么
│  ├─ 收费：谁付费、价值、频次、定价依据
│  └─ 经济性：收入、服务成本、获客成本、体验代价
├─ 验证
│  ├─ 主指标：真实任务或业务结果
│  ├─ 过程：关键流程瓶颈
│  ├─ 护栏：质量、信任、体验、安全、成本
│  └─ 决策：验证条件、扩大、继续实验、调整或停止
└─ 协作
   ├─ 承接：准确复述，不抢他人贡献
   ├─ 分歧：找共同目标，用依据比较
   ├─ 控时：明确下一步，不只报分钟
   └─ 汇报：团队共识、取舍、未决事项与验证
```

框架用于检查遗漏，不是每道题必须依次朗读的目录。

## 题型分流

| 题型 | 优先动作 | 避免 |
| --- | --- | --- |
| 新产品设计 | 具体人物的一次任务、现有替代方式 | 从宏大市场直接跳到十个功能 |
| 老产品优化 | 找到链路卡点并列原因假设 | 看到低使用率就增加入口 |
| 排序 | 先约定目标和比较标准 | 用一堆无依据小数制造确定性 |
| 商业化 | 谁获益、谁付费、成本与体验影响 | 把获客投放支出当成产品收入 |
| AI 产品 | 明确 AI 比非 AI 方案多解决哪一步 | 生成草稿就等于自动完成任务 |
| 数据诊断 | 先看口径与范围，再解释原因 | 先给故事，再挑支持故事的数据 |

## 可复用的组内发言动作

- 框定：“我们最后需要交付哪几项？建议先统一目标，再比较方案。”
- 承接：“沿着刚才提到的使用成本，我补一条具体流程……”
- 质疑：“我认同目标，但这个结论依赖一个尚未确认的前提……”
- 收敛：“这两种方案的分歧是目标人群，不是按钮位置，我们先决定前者。”
- 控时：“目前主流程已经确定，接下来补齐风险和验证，新增功能先记到后续。”
- 修正：“刚才我默认可以获得这类数据，这个前提不成立，我调整入口与验证方式。”

这些是动作例子，不要求逐字背诵。每次发言尽量完成一个推进动作。

## 首期优先级

RICE 可用于比较 Reach、Impact、Confidence、Effort，但各项要有统一窗口和单位。没有数据时，用定性比较与显式假设，比伪造数值更好。

MoSCoW 可帮助约定必须、应该、可以、本期不做。必要的权限、数据质量与失败处理应按实际风险纳入首期，不能因它们不是“亮点”就全部推后。

## 指标最小集

练习时可先选一个主指标、两项诊断指标和两项护栏，数量按题目调整。每项写清对象和口径。

- D7 留存与七日内任意一天回来过不同，必须明确窗口。
- 任务成功不能仅看接口返回成功。
- 成功任务成本需要包含相关失败与重试消耗。
- 付费率与收入改善不能脱离获客、服务成本和留存讨论。
- 效率工具的使用时间越长不一定越好。

## 排练与汇报

练三种短输出：30 秒说明核心价值，45 秒回应一个异议，3 分钟汇报完整方案。只是练习建议，现场规则优先。

汇报顺序可用：结论 → 核心场景与依据 → 主流程与范围 → 取舍风险 → 验证。题目要求名称、Slogan 或排序时应覆盖，但不要把讨论大部分时间用于命名。

## 考前自查

我是否把个人偏好当成了用户事实？我提出的功能是否真的解决选定卡点？我是否知道自己不做什么？这次发言是否接住现场讨论？有什么证据会让我改变结论？
